# 머지 전 검증

검증 대상: $ARGUMENTS

- 위 값이 비어 있으면 `git diff upstream/main...HEAD` 를 검증 대상으로 삼는다.
- 이 Skill 은 **리뷰 세션**의 절차다. 판정과 이슈 보고만 하고, 고치는 일은 만든 세션이 한다.
- 템플릿 · 체크리스트 경로는 모두 **저장소 루트 기준**이다(이 Skill 폴더 기준이 아니다).
  - 절차의 배경: 저장소 루트의 `templates/verification-loop.md`
  - 대조 항목 · 심각도 정의: 저장소 루트의 `templates/approval-checklist.md`

## 1. 요청 범위 확인

- 이 변경으로 무엇을 요청했는지 한 문장으로 확인한다. 인자 · 대화 · PR 설명에서 찾는다.
- 요청 범위가 주어지지 않았으면 **판정하지 말고** 먼저 사용자에게 묻고 멈춘다.

## 2. 변경 파일 목록과 diff 읽기

- 먼저 목록을 본다: `git diff --stat <대상>` (patch 파일이면 `git apply --stat <파일>`).
- 그다음 파일마다 diff 를 읽는다. 필요하면 Read 로 변경 줄의 앞뒤 문맥을 확인한다.
- 변경 파일이 `modern/api` · `modern/web` · 이관 코드(레거시를 옮긴 코드) 중 어디에 속하는지 분류해 둔다. 4단계에서 쓴다.

## 3. 체크리스트 대조

- 저장소 루트의 `templates/approval-checklist.md` 를 읽는다. 항목을 이 Skill 에 옮겨 적지 않고, 그 파일의 현재 내용을 기준으로 삼는다.
- 항목마다 충족 · 미충족 · 확인 필요 중 하나로 표시한다.
- 체크리스트가 `convention-check` Skill 결과를 쓰라고 하면 그 결과를 컨벤션 준수 근거로 쓴다.

## 4. 테스트 실행

변경된 폴더의 테스트만 실행한다. 바뀌지 않은 폴더는 실행하지 않고 "해당 없음"으로 적는다.

| 변경된 곳 | 명령 |
|---|---|
| `modern/api` | `cd modern/api && ./gradlew test` |
| `modern/web` | `cd modern/web && npm test` |
| 이관 코드 | `cd characterization && npm test` (레거시 대상)<br>`cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test` (새 API 대상) |

- 사용량 절약: 전체 로그를 대화에 싣지 않는다. 출력은 scratchpad 파일로 돌려 두고, 통과 · 실패 수와 실패한 테스트 이름만 뽑아 남긴다.
- characterization 은 대상 서버가 떠 있어야 한다. 연결에 실패하면 그 사실을 적고, 어떤 서버(레거시 · `localhost:8080`)를 띄워야 하는지 사람에게 요청한다.
- 의존성이 설치되지 않았거나 서버가 꺼져 실행할 수 없었으면 "실행하지 못함"과 그 이유를 적는다. 통과로 적지 않는다.

## 5. 승인 기준 판정

- 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 충족 · 미충족으로 판정한다.
- 하나라도 미충족이면 **반려**다. 네 기준이 모두 충족되어야 **승인**이다.
- 심각도(치명 / 경고 / 제안)는 체크리스트 파일의 심각도 정의를 따른다.
- 이슈가 0건이면 경고 · 제안 수준까지 한 번 더 훑어본 뒤 판정한다.

## 6. 출력 형식 (순서 고정)

```
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령 · 통과 N / 실패 M · 실패한 테스트 이름 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 이슈 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |
|---|---|---|---|---|
| 1 | 치명 / 경고 / 제안 | path/to/File.java:42 | … | … |

확인 필요
- …
```

- 이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 칸을 모두 채운다.
- 이슈가 없으면 표 대신 "이슈 없음"이라고 적는다.

## 하지 말 것

- 코드를 수정하지 않는다. 고치기 시작하면 그 순간 "만든 쪽"이 된다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"에 남긴다.
- 테스트를 실행하지 않고 통과했다고 쓰지 않는다.
- 요청 범위를 모르는 상태에서 "요청 범위 이탈 없음"을 충족으로 표시하지 않는다.

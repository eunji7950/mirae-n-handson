# 장애 원인 분석(RCA)

- 대상: `incident-logs/$ARGUMENTS/`
- 결과: `docs/rca/$ARGUMENTS.md`
- 인용하는 줄은 모두 `파일:줄번호` 로 적는다. 시각은 모두 KST 로 통일한다.

## 절차

1. **수집 범위** — 파일을 통째로 읽지 않는다. 원인은 아직 추측하지 않는다.
   - `wc -l` · `head` · `tail` 로 파일별 줄 수 · 기록 기간 · 시각 형식을 표로 만든다.
   - 타임존이 명시되지 않은 파일은 다른 로그의 같은 요청과 짝을 맞추거나 epoch 를 환산해 판정하고, 근거와 KST 변환 규칙을 적는다.
   - `grep -c` · `cut` · `awk` · `uniq -c` 로 이상 신호를 분 단위로 집계해 이상 구간과 앞뒤 여유를 정한다.
2. **타임라인** — 이상 이전 · 이상 구간 · 이후로 나눠 사건만 적는다(해석 금지).
   - 모든 줄에 출처 `파일:줄번호` 와 80자 이내 원문 발췌를 붙인다. 반복 메시지는 첫 줄 + "이후 N건/분" 으로 묶는다.
   - 초 단위 해상도 · 응답 완료 시각 기록 · 호스트 시계 차이 때문에 순서를 단정할 수 없는 곳은 **(선후 불확실)** 로 표시한다.
3. **가설** — 증상(풀 타임아웃 · 5xx 등)과 원인을 먼저 구분하고, 서로 다른 축(코드 · DB · 트래픽 · 인프라 등)에서 가설을 **2개 이상** 세운다.
   - 가설마다 근거 줄, **반증 조건**(무엇이 보이면 틀린 것인가), **확인 방법**(실행할 명령)을 표로 적는다.
4. **반증 시도와 판정**
   - 먼저 로그로 반증을 시도한다. 실행한 명령과 결과를 그대로 기록한다.
   - 남은 가설을 코드 · 설정(`modern/api` · `application.yml` 등)과 `파일:줄번호` 로 대조한다.
   - 가설마다 **채택 · 기각 · 판단 불가(로그 부족)** 를 판정하고, 판단 불가면 판정에 필요한 로그를 적는다.
5. **리포트 작성** — `docs/rca/$ARGUMENTS.md` 에 다음 절을 쓴다.
   - 요약: 무엇이 · 언제(KST) · 영향(건수) · 직접 원인 · 배경 원인 · 확신 수준(높음 · 중간 · 낮음)과 그 이유
   - 수집 범위 · 타임라인 · 가설과 검증(1 ~ 4단계 결과)
   - 원인: 직접 원인(인과 사슬 C1, C2 …)과 배경 원인(B1, B2 …). 미확인은 "(미확인)" 으로 표시
   - 근거 로그 줄: 원인 항목별 `파일:줄번호` 와 발췌
   - 수정안(지금 적용) · 재발 방지(구조적 장치) · 모니터링 항목(지표 · 임계값 · 경보)
   - 확인하지 못한 것: 항목 · 확인하지 못한 이유 · 필요한 자료
6. **마스킹** — 리포트를 저장하기 전에 `.claude/skills/rca/masking-rules.md` 의 규칙을 적용한다.
   - 리포트 맨 끝에 유형별 적용 건수 한 줄을 남긴다(`마스킹 적용: IP N건 · 이메일 N건 · …`).

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 인용 전에 `sed -n '<줄>p'` 로 실제 내용을 확인한다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다. 대개 증상이다. 첫 발생 시각과 인과 순서로 판단한다.
- 원본 로그(`incident-logs/`)와 소스 코드를 수정하지 않는다. 수정안은 리포트에만 쓴다.
- 마스킹 대응표(원본 값 ↔ 별칭)를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.

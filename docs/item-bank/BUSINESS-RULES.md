# item-bank 비즈니스 규칙 후보 — 문항 검색 화면(`search.php`)

- 범위: `legacy/item-bank-php/search.php` 와 이 화면이 부르는 `inc/db.php` · `inc/layout.php` · `vendor/simplelog/Log.php` · `v_item_public`
- 경로 표기에서 `legacy/item-bank-php/` 는 생략합니다. 스키마 · 시드는 `db/mariadb/init/` 기준입니다.
- 실행 환경은 PHP 7.4(`Dockerfile:1`)입니다. 형변환 동작은 PHP 7.4 기준으로 읽었습니다.
- 이 화면은 읽기 전용입니다. 모든 규칙은 `GET /search.php` 한 경로에 적용됩니다.
- 모델이 코드로 대조했을 뿐, 사람이 검증한 규칙은 아직 없습니다.

### BR-01 공개 문항만 검색된다
- ID: BR-01
- 규칙: 검색 건수와 결과 행은 `item.status = 'A'`(공개)인 문항에서만 나오고, `D`(삭제) · `R`(검수중) 문항은 어떤 조건에서도 나오지 않는다.
- 근거 파일:줄번호: `db/mariadb/init/01-schema.sql:52`, `:70` · `search.php:521-526`
- 근거 코드 인용:
  - `CREATE OR REPLACE VIEW v_item_public AS` / `WHERE i.status = 'A';`
  - `$from   = " FROM v_item_public";`
  - `$countSql = "SELECT COUNT(*) AS cnt" . $from . $where;`
- 확신도: 높음
- 비고: 상태 코드 의미(A=공개 D=삭제 R=검수중)는 스키마 주석(`01-schema.sql:26`)에만 있습니다. 필터 값 `'A'` 는 코드로 확인했습니다. 선택 목록(단원 · 태그)은 뷰가 아니라 원본 테이블에서 읽으므로 공개 문항이 없는 단원 · 태그도 목록에 나옵니다(BR-14).

### BR-02 난이도를 지정하지 않으면 난이도 5 문항이 빠진다
- ID: BR-02
- 규칙: `level` 파라미터가 없거나 trim 후 빈 문자열이면 `level < 5` 조건이 붙어 난이도 1~4 문항만 조회된다.
- 근거 파일:줄번호: `search.php:211-216`
- 근거 코드 인용:
  ```php
  $level = trim($level);

  // 난이도 값이 비어 있으면 전체 난이도 검색 (1~5 모두 포함)
  if ($level == '') {
      $where .= " AND level < 5";
  }
  ```
- 확신도: 높음(코드 동작 기준)
- 비고:
  - 주석(`:213`)과 드롭다운 문구 `'전체'`(`:192`)는 "1~5 모두 포함"이라고 하지만, 코드는 5를 뺍니다. 의도인지 결함인지는 코드로 판단할 수 없습니다. 이관 전에 사람이 정해야 합니다.
  - 파라미터 없이 처음 열 때도 적용됩니다. 이때 조건 요약은 "조건 없이 검색했습니다."로 나와서(`:355-356`) 난이도 조건이 붙었다는 사실이 화면에 드러나지 않습니다(BR-13).
  - 시드 기준 공개 문항 26건 중 20건만 나오고 한 페이지로 끝납니다(`02-seed.sql:33-34`).
  - 태그 `서술형`(`02-seed.sql:24`)은 난이도 5 문항(25~28, 30)에만 붙어 있습니다(`02-seed.sql:101-106`). 그래서 난이도를 비우고 이 태그로 검색하면 0건입니다. 실제로 실행해 보지는 않았고 시드로 계산한 결과입니다.
  - 난이도 5 문항은 `level=5` 를 명시해야만 나옵니다(BR-03).

### BR-03 난이도 값 해석 — 1~5 는 정확 일치, 그 밖의 값은 정수로 바꿔 비교
- ID: BR-03
- 규칙: trim 한 `level` 이 한 글자 `1`~`5` 이면 `level = 그 값` 으로 조회한다. 그 밖의 비어 있지 않은 값이면 경고 "난이도는 1~5 사이여야 합니다."를 띄우고 `(int)` 로 바꾼 값과 `level = ?` 으로 비교한다(조회는 막지 않는다).
- 근거 파일:줄번호: `search.php:217-230`
- 근거 코드 인용:
  ```php
  else if (preg_match('/^[1-5]$/', $level)) {
      $where .= " AND level = ?";
  ...
  else {
      // 1~5 밖의 값은 그대로 정수로 비교한다 (대개 0건)
      $warnings[] = '난이도는 1~5 사이여야 합니다.';
      $where .= " AND level = ?";
      $types .= 'i';
      $values[] = (int)$level;
  ```
- 확신도: 높음(분기) / 중간(형변환 결과)
- 비고:
  - PHP 7.4 의 `(int)` 는 앞쪽 숫자만 읽습니다. 그래서 `03` · `3abc` · `3.9` 는 경고와 함께 난이도 3으로 조회되고, `abc` 는 0 이 되어 0건이 나올 것으로 봅니다(실행 확인 안 함).
  - `item.level` 에는 CHECK 제약이 없습니다(`01-schema.sql:25`, 주석만 1~5). 따라서 "0건"은 데이터에 달려 있고 스키마가 보장하지 않습니다.
  - 요약 문구는 1~5 는 원문(`:221`), 그 밖의 값은 `(int)` 결과(`:229`)로 표시됩니다.

### BR-04 키워드는 제목 또는 지문 부분 일치, 최대 100자
- ID: BR-04
- 규칙: `q` 를 trim 한 뒤 100자(`mb_strlen`, UTF-8 문자 단위)를 넘으면 100자로 자르고 경고한다. 비어 있지 않으면 `title LIKE %q% OR stem LIKE %q%` 로 조회한다.
- 근거 파일:줄번호: `search.php:85-101` · 화면 `search.php:494`
- 근거 코드 인용:
  ```php
  $q = trim($q);
  if (mb_strlen($q, 'UTF-8') > 100) {
      $q = mb_substr($q, 0, 100, 'UTF-8');
      $warnings[] = '키워드가 너무 길어 100자까지만 사용했습니다.';
  }
  ...
      $like = '%' . $q . '%';
      $where .= " AND (title LIKE ? OR stem LIKE ?)";
  ```
  화면: `'<input type="text" id="q" name="q" size="30" maxlength="100" value="' . h($q) . '">'`
- 확신도: 높음
- 비고:
  - 같은 100자 제한이 두 층에 있습니다. 화면은 `maxlength="100"`(`:494`)이고 서버는 절단합니다(`:86-89`). URL 로 직접 보내면 서버 절단만 적용됩니다.
  - `%` · `_` 는 이스케이프하지 않고 와일드카드로 쓰며 경고만 띄웁니다(`:94-96`).
  - 한 글자 키워드는 경고만 띄웁니다(`:91-93`).
  - 대소문자 구분 여부는 콜레이션 `utf8mb4_unicode_ci`(`01-schema.sql:33`)를 보고 "구분 안 함"으로 추정했습니다.

### BR-05 단원은 코드 정확 일치, 형식 · 대소문자 경고는 조회를 막지 않는다
- ID: BR-05
- 규칙: `unit` 을 trim 한 값이 비어 있지 않으면 `unit_code = ?` 로 조회한다. 형식(`^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$`)이 틀리거나 소문자가 섞여 있으면 경고만 추가하고 입력값 그대로 조회한다.
- 근거 파일:줄번호: `search.php:109-120`
- 근거 코드 인용:
  ```php
  if (!preg_match('/^[A-Za-z][0-9]{1,2}-[0-9]{1,2}$/', $unit)) {
      // 형식이 달라도 그대로 조회한다 (결과는 대개 0건)
      $warnings[] = '단원 코드 형식이 올바르지 않습니다. (예: M5-1)';
  }
  if ($unit !== strtoupper($unit)) {
      $warnings[] = '단원 코드는 대문자로 입력하세요. (입력값 그대로 조회합니다)';
  }
  $where .= " AND unit_code = ?";
  ```
- 확신도: 중간
- 비고:
  - 콜레이션이 `utf8mb4_unicode_ci`(`01-schema.sql:18`)라서 `m5-1` 도 `M5-1` 문항과 일치할 것으로 추정합니다. 그러면 대문자 경고가 떠도 결과는 나옵니다.
  - 드롭다운 선택 표시는 PHP 엄격 비교(`$r['code'] === $unit`, `:162`)라서 소문자로 입력하면 어떤 단원도 선택되지 않은 상태로 그려집니다.
  - 모두 실행해 보지 않은 추정입니다.

- 근거 파일:줄번호: `search.php:123-146`

  ```php
  $stmt = $conn->prepare("SELECT name, grade FROM unit WHERE code = ?");
  ...
  if ($unitName === '') {
      $warnings[] = '등록되지 않은 단원 코드입니다: ' . $unit;
  ```

- 확신도: 높음
- 비고:
  - `prepare` · `execute` · `get_result` 가 실패해도 예외 없이 넘어가서(`:126-139`, `mysqli_report(MYSQLI_REPORT_OFF)` = `inc/db.php:20`) `$unitName` 이 빈 값으로 남습니다. 이때는 등록된 단원인데도 이 경고가 뜹니다.
  - 형식 경고(BR-05)와 동시에 뜰 수 있습니다.

### BR-07 태그는 이름 정확 일치, 최대 50자
- ID: BR-07
- 규칙: `tag` 를 trim 한 값이 비어 있지 않으면 50자를 넘는 부분을 잘라 경고한다. 그 이름의 태그가 붙은 문항만 `EXISTS (… t.name = ?)` 로 조회한다. `%` · `_` 가 있으면 "부분 일치를 지원하지 않습니다." 경고를 띄우고, 이 문자들은 리터럴로 비교한다.
- 근거 파일:줄번호: `search.php:235-248`
- 근거 코드 인용:
  ```php
  if (mb_strlen($tag, 'UTF-8') > 50) {
      $tag = mb_substr($tag, 0, 50, 'UTF-8');
      $warnings[] = '태그 이름이 너무 길어 50자까지만 사용했습니다.';
  }
  $where .= " AND EXISTS (SELECT 1 FROM item_tag it JOIN tag t ON t.id = it.tag_id"
          . " WHERE it.item_id = v_item_public.id AND t.name = ?)";
  ```
- 확신도: 높음
- 비고:
  - 50자는 `tag.name VARCHAR(50)`(`01-schema.sql:37`)과 같습니다.
  - 화면에서는 select 로만 고를 수 있습니다(`:485-492`). 자유 입력은 URL 로만 가능합니다.
  - 태그 조건은 BR-02 의 `level < 5` 와 AND 로 묶입니다.

### BR-09 정렬 기준과 기본 정렬
- ID: BR-09
- 규칙: `sort` 는 소문자로 바꾼 뒤 `id` · `title` · `unit` · `level` · `created` 만 인정한다. 비었거나 알 수 없는 값이면 `level DESC, id ASC` 로 정렬한다(알 수 없는 값은 경고를 띄운다). `dir` 은 `asc` · `desc` 외의 값이면 경고를 띄우고 비운다.
- 근거 파일:줄번호: `search.php:266-327`
- 근거 코드 인용:
  ```php
  case '':
      // 기본 정렬: 어려운 문항부터, 같은 난이도면 번호 순
      $orderBy = " ORDER BY level DESC, id ASC";
  ...
  default:
      $warnings[] = '알 수 없는 정렬 기준입니다. 기본 정렬을 사용합니다.';
  ```
- 확신도: 높음
- 비고: 기준마다 `dir` 이 비었을 때의 방향이 다릅니다.
  | sort | dir 비었을 때 | ORDER BY(asc / desc) | 근거 |
  |---|---|---|---|
  | id | asc | `id ASC` / `id DESC` | `:277-283` |
  | title | asc | `title ASC, id ASC` / `title DESC, id ASC` | `:285-291` |
  | unit | asc | `unit_code ASC, level DESC, id ASC` / `unit_code DESC, level DESC, id ASC` | `:293-299` |
  | level | **desc** | `level ASC, id ASC` / `level DESC, id ASC` | `:301-307` |
  | created | **desc** | `created_at ASC, id ASC` / `created_at DESC, id ASC` | `:309-315` |
  - `unit` 정렬의 2차 키 `level DESC` 는 방향과 상관없이 고정입니다.
  - 화면에 보이는 방향 값은 `:328-331` 에서 같은 기준으로 채웁니다.
  - `created` 는 열 머리글 링크가 없어서(`:392-397`) URL 로만 쓸 수 있습니다.

### BR-11 페이지 크기 20건, 페이지 번호 1~999
- ID: BR-11
- 규칙: 한 페이지는 20건이고 `OFFSET (page-1)*20` 을 쓴다. `page` 가 숫자로만 되어 있으면 그 값을 쓰되 1 미만은 1, 999 초과는 999(경고)로 바꾼다. 숫자가 아니면 1페이지를 보여 준다(값이 빈 문자열이나 `1` 이 아닐 때만 경고).
- 근거 파일:줄번호: `search.php:336-349`, `:523`, `:553`
- 근거 코드 인용:
  ```php
  if (preg_match('/^[0-9]+$/', $pageRaw)) {
      $page = (int)$pageRaw;
  } else if ($pageRaw !== '' && $pageRaw !== '1') {
      $warnings[] = '페이지 번호가 올바르지 않아 1페이지를 표시합니다.';
  }
  if ($page < 1) {
      $page = 1;
  }
  if ($page > 999) {
      $page = 999;
  ```
- 확신도: 높음
- 비고:
  - `page=0` 은 경고 없이 1페이지가 됩니다. `page=-1` 은 정규식에 걸리지 않아 경고가 뜹니다.
  - `page` 는 trim 하지 않습니다.
  - 마지막 페이지보다 큰 번호(예: 20건일 때 `page=2`)는 줄이지 않습니다. 건수는 0보다 크므로 BR-12 의 "결과 없음"으로 가지 않고, 행이 없는 빈 표가 나옵니다(`:657`, `:663-681`).

  ```php
  }
  ...
  $pages = (int)ceil($total / $pageSize);
  if ($pages > 1) {
  ```
- 확신도: 높음
- 비고:
  - 0건 판정은 COUNT 결과 기준입니다. 현재 페이지의 행 수와는 관계없습니다(BR-11 비고 참고).
  - 페이지 번호는 생략 없이 전부 출력합니다(`:692-698`).
  - 페이지 링크는 조건과 sort · dir 을 유지합니다(`:423-430`).

### BR-13 조건 요약 문구
- ID: BR-13
- 규칙: 요약 항목(키워드 · 단원 · 난이도 · 태그)이 하나도 없으면 "조건 없이 검색했습니다."를 출력하고, 있으면 목록으로 출력한다. 정렬 기준이 있으면 "정렬: <sort> <dir>"을 덧붙인다.
- 근거 파일:줄번호: `search.php:354-366`
- 근거 코드 인용:
  ```php
  if (empty($summary)) {
      $summaryHtml = '<p class="summary">조건 없이 검색했습니다.</p>' . "\n";
  ```
- 확신도: 높음
- 비고:
  - 난이도가 비었을 때 붙는 `level < 5`(BR-02)는 요약에 들어가지 않습니다(`:214-216` 에 `$summary[]` 가 없음).
  - 기본 정렬(`sort` 없음)도 요약에 나오지 않습니다.

### BR-14 검색 폼 선택 목록
- ID: BR-14
- 규칙: 단원 목록은 `unit` 전체를 `grade ASC, code ASC` 로 읽어 학년별 `optgroup` 으로 보여 준다. 태그 목록은 `tag` 전체를 `id ASC` 로 보여 준다. 난이도는 전체(빈 값)와 1~5 고정 라벨이다.
- 근거 파일:줄번호: `search.php:156`, `:178`, `:193-199`, `:452-462`
- 근거 코드 인용:
  - `$res = $conn->query("SELECT code, name, grade FROM unit ORDER BY grade ASC, code ASC");`
  - `$res = $conn->query("SELECT name FROM tag ORDER BY id ASC");`
  - `5 => '5 (최상)',`
- 확신도: 높음
- 비고:
  - 공개 문항 수와 관계없이 모든 단원 · 태그가 나옵니다.
  - 단원 조회가 실패하면 `$unitGroups` 가 비고, 두 번째 분기(`:463-471`)가 `$unitOptions` 에서 빈 값을 뺀 나머지를 출력합니다. 이 경우 나머지도 비어 있어서 "전체 단원"만 남습니다.

### BR-15 오류 처리 — DB 연결 실패와 검색 실패
- ID: BR-15
- 규칙: DB 연결에 실패하면 예외 메시지("DB 연결 실패: …")와 새로 고침 안내를 출력하고 종료한다. 조건 조립이나 조회 중 `RuntimeException` 이 나면 `Log::error` 로 기록하고 "검색 중 오류가 발생했습니다."만 출력한다.
- 근거 파일:줄번호: `inc/db.php:20-26` · `search.php:712-729`
- 근거 코드 인용:
  ```php
  throw new RuntimeException('DB 연결 실패: ' . $err);
  ```
  ```php
  } catch (RuntimeException $e) {
      Log::error('search failed', array('msg' => $e->getMessage()));
      echo '<p class="error">검색 중 오류가 발생했습니다.</p>' . "\n";
  ```
- 확신도: 높음
- 비고:
  - 연결 실패 때는 DB 오류 원문(`connect_error`)이 이스케이프된 상태로 화면에 나갑니다(`search.php:715`).
  - 바인딩 개수 불일치 예외(`:536-539`)는 현재 코드에서 **도달 불가**로 봅니다. `$types` 에 글자를 붙이는 모든 곳에서 같은 수의 `$values` 를 붙이기 때문입니다(`:99-101`, `:119-120`, `:219-220`, `:227-228`, `:246-247`). 스키마 제약이 아니라 코드 구조로 막힌 경우입니다.
  - `RuntimeException` 이 아닌 오류(PHP Error 등)는 잡지 않습니다. `display_errors = Off`(`Dockerfile:9`)이므로 화면이 중간에 끊길 것으로 추정합니다.
